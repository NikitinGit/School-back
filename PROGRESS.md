# Состояние работ: эндпоинты для Проектов и Задач

Задача практикума: «Добавить в код эндпоинты, связанные с новыми функциями фронтенда».

Новые возможности — **Проекты** и **Задачи**. На сайте и в мобильном приложении они
работают на заглушках (данные лежат в памяти браузера и телефона), на сервере их нет
совсем. Эта работа — серверная часть.

## Смежные проекты

| Проект | Путь | Что там |
|---|---|---|
| Сайт | `../school-bonus-web` | Next.js. Заглушки в `lib/dashboard-storage.ts`, страницы `projects` и `tasks` |
| Мобильное приложение | `../a-bonus` | Expo. 14 файлов `mock*`, 9 экранов на заглушках |

Модель данных согласована по схеме в Figma — файл «Мобильное приложение для учеников»,
вторая схема (с зелёным заголовком).

В мобильном приложении проработан полный цикл сдачи задач, которого на сайте нет:
ученик отправляет ответ, преподаватель принимает или возвращает на доработку.
Серверная часть сделана по этой, более полной, модели.

## Принятые решения

1. **Опыт достаётся первым N сдавшим.** Поля `reward_exp` и `reward_exp_slots`.
   Служба при принятии ответа считает уже принятых через
   `TaskAnswerRepository.countStudentsWithStatus(taskId, ACCEPTED)` и начисляет опыт,
   только если их меньше, чем слотов. Пустое значение слотов — опыт всем сдавшим.

2. **Лента проектов собирается одним запросом на страницу.** Число отметок, число
   комментариев, отметил ли смотрящий, его группы — всё берётся пакетными методами
   хранилищ и передаётся в `ProjectViewContext`. Запрашивать по одному проекту нельзя:
   страница из двадцати проектов даст под сотню обращений к базе.

3. **При изменении пустые поля не затирают старые значения.** Так сделано в методах
   `applyUpdate` обоих преобразователей.

4. **Видимость проекта** — перечисление `ALL_STUDENTS` / `GROUP_ONLY` плюс ссылка на
   группу. Признаки `inMyGroup`, `mine`, `likedByMe` вычисляются на сервере
   относительно спрашивающего. Проверка доступа — `ProjectRepository.isVisibleTo`,
   для задач `TaskRepository.isVisibleToStudent`.

5. **Состояния сдачи:** `SUBMITTED`, `ACCEPTED`, `REVISION`. Отсутствие записи означает
   «не сдавал». Признаки «активна» и «просрочена» клиент выводит из `dateTo` — в базе
   их нет.

6. **Попытки сдачи копятся, а не перезаписываются.** Номер следующей — через
   `TaskAnswerRepository.findLastAttempt`.

7. **Сущности сравниваются только по номеру**, отпечаток постоянный, используется
   `Hibernate.getClass()` вместо обычного `getClass()` — иначе отложенно загруженный
   объект не совпал бы сам с собой. Проверено живыми запросами на добавлении и
   удалении ученика из группы.

8. **Преобразователи не наследуют `ConverterModelAssembler`.** Он рассчитан на
   изменяемые объекты с методами установки значений, а у записей их нет. Взят образец
   `EnrollmentHistoryAssembler` — он в проекте тоже обычный компонент.

9. **Отметки «нравится» хранятся таблицей, а не счётчиком.** Счётчиком нельзя ответить
   на вопрос «отметил ли я», который нужен мобильному приложению, и нельзя запретить
   повторное нажатие.

## Готовые адреса

Все закрыты входом по логину и паролю, права проверяются и по роли, и по владению.

### Задачи

| Метод | Адрес | Кому | Назначение |
|---|---|---|---|
| GET | `/api/tasks` | ADMIN, TEACHER | выданные задачи; преподаватель видит свои, администратор все |
| GET | `/api/tasks/my` | STUDENT | свои задачи с состоянием своей последней сдачи; отбор `filter` |
| GET | `/api/tasks/{id}` | ADMIN, TEACHER | одна задача |
| GET | `/api/tasks/my/{id}` | STUDENT | одна задача вместе со своей сдачей |
| POST | `/api/tasks` | ADMIN, TEACHER | выдать задачу группам |
| PUT | `/api/tasks/{id}` | ADMIN, TEACHER | изменить; пустые поля не меняются |
| DELETE | `/api/tasks/{id}` | ADMIN, TEACHER | удалить |
| GET | `/api/groups/{groupId}/tasks` | все роли | задачи группы; отбор `filter` |
| POST | `/api/tasks/{id}/answers` | STUDENT | сдать ответ (новая попытка) |
| GET | `/api/tasks/{id}/answers` | ADMIN, TEACHER | сдачи по задаче на проверку |
| GET | `/api/tasks/{taskId}/answers/{studentId}` | все роли | все попытки ученика; ученик — только свои |
| PUT | `/api/tasks/{taskId}/answers/{studentId}` | ADMIN, TEACHER | принять или вернуть на доработку |

### Проекты

| Метод | Адрес | Кому | Назначение |
|---|---|---|---|
| GET | `/api/projects` | все роли | лента; отбор `scope` = ALL, MY, GROUP (+ `groupId`) |
| GET | `/api/projects/{id}` | все роли | один проект |
| POST | `/api/projects` | все роли | опубликовать |
| PUT | `/api/projects/{id}` | автор, ADMIN | изменить |
| DELETE | `/api/projects/{id}` | автор, ADMIN | удалить вместе с отметками и комментариями |
| POST | `/api/projects/{id}/like` | все роли | отметить; повтор ошибкой не считается |
| DELETE | `/api/projects/{id}/like` | все роли | снять отметку |
| GET | `/api/projects/{id}/comments` | все роли | комментарии, от старых к новым |
| POST | `/api/projects/{id}/comments` | все роли | добавить комментарий |
| DELETE | `/api/projects/{projectId}/comments/{commentId}` | автор комментария, автор проекта, ADMIN | удалить комментарий |

Опыт и уровень добавлены в ответ о пользователе: `exp` и `rank_level` в `UserDTO`,
только для чтения. Имя `exp` выбрано под сайт: он читает поле именно так
(`school-bonus-web/app/(dashboard)/users/page.tsx`).

### Правила, зашитые в службы

- **Награда.** Монеты получает каждый, чей ответ приняли. Опыт — только первые
  `reward_exp_slots` учеников; если ограничение не задано, опыт получают все.
  Число уже принятых считается **до** того, как принят текущий ответ, иначе ученик
  занимал бы своё же место среди первых.
- **Уровень** пересчитывается от опыта: единица плюс по одному за каждые 100 опыта
  (`UserService.EXPERIENCE_PER_RANK`). Значение условное — в описании возможности
  порог не задан, поэтому вынесено в одно место.
- **Попытки.** Сдать заново можно только после возврата на доработку. Пока ответ ждёт
  проверки или уже принят — повторная сдача отклоняется. Прежние попытки и замечания
  к ним остаются в базе.
- **Сроки.** До даты начала и после даты окончания сдать нельзя.
- **Права на задачу.** Править и проверять может выдавший её преподаватель или
  администратор. Преподаватель выдаёт задачи только своим группам.
- **Видимость проекта.** Ученик видит проект, открытый всем, свой собственный и проект
  своей группы. Преподаватель и администратор видят все.

## Известные недостатки, оставленные нетронутыми

Найдены попутно, к задаче отношения не имеют.

1. **Разнотипные номера строк.** В пяти старых таблицах (`users`, `groups`, `presents`,
   `photos_presents`, `enrollment_history`) столбец `id` создан 32-разрядным, а в
   классах объявлен 64-разрядным. Из-за этого нельзя включить строгую сверку схемы на
   рабочей базе. Чинится одним изменением из пяти строк — проверено на временной базе,
   работает.

2. **Пароль обязателен при любом изменении пользователя.** Чтобы поменять одно имя,
   клиент должен заново прислать пароль, иначе приходит `rawPassword cannot be null`.

3. **Добавление ученика в группу** требует указать его номер дважды: в адресе и в
   параметрах запроса.

4. **В `enrollment_history` нет ссылки на задачу**, поэтому записать, за какую именно
   задачу начислены монеты, пока нельзя. Сейчас название задачи пишется в поле
   `description` текстом. Понадобится ещё одно изменение базы.

5. **Любая ошибка отдаётся как 400.** `RestExceptionHandler` переводит все исключения
   в один код, поэтому «нет прав» и «не найдено» клиент не отличит от «неверный
   запрос». Отказ по роли от Spring Security тоже приходит как 400. Трогать не стал:
   это поведение всех прежних адресов, менять его надо отдельно и всем вместе.

6. **Монеты обнуляются при правке пользователя.** Правка собирает пользователя заново
   из присланных полей, поэтому `coins` клиент обязан присылать обратно. Для опыта и
   уровня это закрыто (переносятся из сохранённого), для монет — прежнее поведение.

## Как проверять работу

1. **Текст запросов к базе** — прогнать в откатываемой транзакции:
   `docker exec -i school-db psql -U postgres -d school -v ON_ERROR_STOP=1`,
   обернув всё в `BEGIN;` и `ROLLBACK;`
2. **Сборка:** `sh gradlew build` — включает основной тест
3. **Запуск приложения:** Spring при старте разбирает имена всех методов хранилищ и
   тексты всех запросов. Опечатка в любом — приложение не поднимется
4. **Строгая сверка схемы** на временной базе: создать `school_validate`, прогнать
   изменения, расширить пять старых столбцов до 64 разрядов, запустить с
   `--spring.jpa.hibernate.ddl-auto=validate`, удалить базу
5. **Живые запросы:** `curl -u admin:admin http://localhost:8080/api/...`.
   Пройдено целиком: выдача задачи, сдача, возврат на доработку, повторная попытка,
   принятие, начисление монет и опыта, рост уровня, запись в историю; публикация
   проектов обоих видов видимости, отметки и их снятие, комментарии, удаление; и
   отказы — чужой преподаватель, посторонний ученик, чужой комментарий, срок задом
   наперёд, пустой ответ. В базе `school` после проверки остались тестовые
   пользователи `teach1`, `teach2`, `stud1`–`stud3`, группа `ПИ-101` и их задачи
